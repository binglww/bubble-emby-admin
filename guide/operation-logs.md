# 操作日志

操作日志记录管理员在后台执行的操作，用于事后追溯和责任界定。

后台入口：`运维` -> `操作日志`。

## 记录内容

每条日志包含以下字段：

| 字段 | 说明 |
| --- | --- |
| 时间 | 操作发生的时间 |
| 管理员 | 执行操作的管理员；管理员已删除时显示其 ID |
| 操作 | 操作类型 |
| 目标 | 被操作的对象，通常是用户名或 Emby 用户 ID |
| 结果 | 操作是否成功 |
| 请求 ID | 本次请求的唯一标识 |
| 详情 | 操作的原始参数与返回，展开后查看 |

## 筛选

列表支持按以下条件筛选：

- 操作类型
- 管理员，或直接填写管理员 ID 查询已删除的管理员
- 结果
- 开始日期与结束日期
- 目标用户名或 Emby ID，支持模糊匹配
- 精确 Emby 用户 ID
- 请求 ID

筛选条件可组合使用。选择 `重置` 清空全部条件。

## 请求 ID 的用法

同一次操作在操作日志和运行日志中使用相同的请求 ID。排查问题时，可以先在操作日志中定位到具体操作，复制请求 ID，再到 `运维` -> `运行日志` 中检索，查看该次请求的完整执行过程。

在日志行中选择 `查看` 可以复制请求 ID。浏览器禁止访问剪贴板时复制会失败，此时手动选中文本复制。

## 与运行日志的区别

| | 操作日志 | 运行日志 |
| --- | --- | --- |
| 记录对象 | 管理员在后台执行的操作 | 服务端运行过程中的日志输出 |
| 用途 | 追溯谁在什么时间做了什么 | 排查错误原因和执行细节 |
| 保留方式 | 存入数据库，可长期检索 | 按运行时输出，用于实时查看 |

## 常见情况

### 管理员一栏显示为 ID

该管理员账号已被删除。日志保留操作发生时的管理员 ID，可在筛选条件中填写该 ID 查询其全部历史操作。

### 详情无法展开

详情内容为操作发生时记录的原始数据。格式异常时页面会提示无法解析，此时可通过请求 ID 到运行日志中查找对应记录。

### 找不到某次操作的记录

确认筛选条件中的日期范围覆盖了操作发生的时间，并检查是否设置了过窄的操作类型或结果条件。
