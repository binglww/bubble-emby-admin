# 积分与签到

积分系统为用户提供一套可自行积累和消耗的数值，可用于每日签到、积分保号和积分商城。系统默认关闭，开启后才会在用户中心显示相关入口。

## 开启积分

后台入口：`配置中心` -> `积分与签到`。

| 配置项 | 说明 |
| --- | --- |
| 开启积分系统 | 积分总开关，关闭后所有积分相关功能不可用 |
| 积分名称 | 用户端展示的名称，最长 32 个字符，例如积分、硬币、星光 |
| 开启每日签到 | 控制用户中心是否显示签到按钮 |
| 每日签到最小奖励 | 单次签到的奖励下限，开启签到时必须大于 0 |
| 每日签到最大奖励 | 单次签到的奖励上限，不能小于最小奖励 |

关闭积分系统后，签到、积分商城和积分保号都会同时停用。已产生的积分余额和流水会保留，重新开启后继续可用。

## 每日签到

用户在用户中心的积分卡片中签到，每天一次，奖励在配置的最小值和最大值之间随机产生。签到成功后余额立即更新，当天不能重复签到。

用户可在 `签到记录` 中查看近 60 天的签到日历，日历会标出已签到的日期和当天获得的奖励。

### 签到验证码

配置 Cloudflare Turnstile 后，签到前需要先完成人机验证。未配置验证码时，点击签到按钮直接提交。

验证码相关配置见 `配置中心` -> `基础`。

### 按用户组提高奖励

用户组可以单独配置签到奖励区间。用户同时命中多个用户组时，优先取最大奖励更高的区间；最大奖励相同时，再取最小奖励更高的区间。配置方式见[用户分组](/guide/membership-groups)。

## 积分流水

每一次积分变动都会记录一条流水，包含变动数量、变动后余额、来源和时间。

| 来源 | 触发方式 |
| --- | --- |
| 签到获得 | 用户完成每日签到 |
| 管理员赠送 | 管理员在积分详情页手动增加 |
| 管理员扣减 | 管理员在积分详情页手动扣减 |
| 积分保号 | 会员到期时按积分保号规则扣减 |
| 商城购买 | 用户在积分商城下单 |

用户可在用户中心的积分卡片中查看本人流水；管理员可在 `运营` -> `积分中心` 查看全站流水，并按用户、来源、变动类型、操作者和日期筛选。

## 积分中心

后台入口：`运营` -> `积分中心`。

积分中心提供统计概览、积分流水和积分排行：

- 近 15 天签到人数
- 积分余额分布
- 积分获得与消耗排行
- 保号扣减趋势
- 近 15 天积分收入与消耗趋势

排行榜中的用户可以点击进入该用户的积分详情页。

## 用户积分详情

在 `用户管理` 的用户详情中选择 `积分详情`，或从积分中心的排行榜进入。

积分详情页展示该用户的当前积分、最近签到、30 天与 60 天积分变化趋势和完整流水，并提供赠送和扣减积分的入口。管理员的每次调整都会写入流水，并可配置为向该用户发送 Telegram 私信通知。

## 积分保号

开启后，会员到期时系统会尝试扣减指定积分为用户续期，扣减成功即按配置的天数自动续费。

在 `配置中心` -> `积分与签到` 中配置：

- `启用积分保号规则`
- `积分保号扣减积分`：单次扣减数量，必须大于 0

启用积分保号前需要先开启积分系统。积分保号可与观看保号同时启用，两者的判定关系见[观看保号](/guide/watch-keepalive)。

用户余额不足以支付扣减积分时不会续期，账号按到期流程处理。

## 常见情况

### 用户中心没有积分卡片

检查 `开启积分系统`。该开关关闭时，用户中心不显示积分卡片，签到和商城入口也不会出现。

### 有积分卡片但没有签到按钮

检查 `开启每日签到`。该开关关闭时，积分卡片仍会显示余额和流水入口，只是不显示签到按钮。

### 保存配置时提示扣减积分必须大于 0

启用积分保号规则时，`积分保号扣减积分` 必须填写大于 0 的数值。

### 保存配置时提示请先开启积分系统

积分保号依赖积分系统，需要先开启 `开启积分系统` 再启用积分保号规则。
