# 工单系统

`工单系统` 用于处理用户账号、播放、续费等客服类问题。工单独立于 `求片` 功能，不会复用求片工单数据。

## 用户入口

用户可在 `用户中心` -> `工单` 提交和查看自己的工单。

支持内容：

- 选择工单类型
- 填写标题和内容
- 可选上传 1 张图片
- 查看工单状态和消息时间线
- 在管理员回复后补充内容
- 主动关闭未关闭工单

图片限制：

- 仅支持 `JPG`、`PNG`、`WebP`
- 最大 `5MB`
- 每个工单最多 1 张图片
- 图片走鉴权访问，仅提交用户本人和管理员可查看

## 状态说明

工单状态包括：

- `等待管理员`：用户已提交或已补充，等待管理员处理
- `等待用户`：管理员已回复，等待用户补充
- `已关闭`：用户或管理员已关闭，双方都不能继续回复

用户只能在 `等待用户` 状态补充一次内容。用户补充后状态会回到 `等待管理员`。系统不限制单个工单生命周期内的补充总次数，但每一轮补充都必须由管理员回复后触发。

管理员可在未关闭工单中回复或关闭。管理员在 `等待用户` 状态继续回复时，工单仍保持 `等待用户`，不会给用户叠加多次补充机会。

## 后台管理

后台入口：`运营` -> `工单管理`

管理员可执行：

- 按状态、类型和关键词筛选工单
- 查看工单详情、图片和消息时间线
- 回复工单
- 关闭工单

用户关闭、管理员关闭都不会发送 Telegram 通知。关闭后的工单不能再回复。

## 工单配置

配置入口：`配置中心` -> `工单`

可配置内容：

- 工单类型名称
- 类型说明
- 启用或禁用
- 排序
- Telegram 接收管理员

禁用类型不会出现在用户提交入口中，历史工单仍可查看、回复和关闭。

Telegram 接收人只展示启用中的管理员，并标识该管理员是否已绑定 Telegram。未绑定 Telegram 的管理员即使被配置为接收人，也不会实际收到通知。

## Telegram 通知

工单通知复用系统通知链路。

会发送管理员通知的动作：

- 用户提交新工单
- 用户补充工单

不会发送通知的动作：

- 管理员回复
- 用户关闭
- 管理员关闭

通知发送需要同时满足：

- Telegram 服务已开启
- Telegram 管理员通知已开启
- `配置中心` -> `通知` 中 `工单通知` 已开启
- 工单类型配置了该管理员为接收人
- 管理员个人通知偏好中 `工单通知` 已开启
- 管理员账号有效且已绑定 Telegram

工单通知模板位于 `配置中心` -> `通知` -> `通知模板`。

内置模板：

- `管理员新工单通知`
- `工单用户补充通知`

模板可使用工单编号、类型、用户、标题、内容摘要和后台链接等变量。工单图片不会直接推送到 Telegram 模板中。
