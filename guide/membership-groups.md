# 用户分组

用户分组用于把用户归类，供公告投放、线路展示、批量操作和权益配置复用。分组分为手动用户组和智能用户组两种。

后台入口：`用户` -> `用户分组`。

## 两种分组类型

| 类型 | 成员来源 | 适用场景 |
| --- | --- | --- |
| 手动用户组 | 管理员逐个或批量添加、移除 | 成员固定、需要精确控制的场景 |
| 智能用户组 | 按规则实时归类，不需要手动维护 | 按状态、时间或行为动态变化的场景 |

智能用户组的成员在每次使用时按当前规则重新计算，不保存固定名单。用户状态变化后，归属会自动跟随，无需手动调整。

## 手动用户组

新建分组时选择手动类型，保存后即可添加成员。

在分组详情中可以搜索用户名、用户 ID 或备注来查找并添加成员，也可以勾选多个成员后批量移除。移除成员只解除分组关联，不会删除用户，也不会改变会员状态。

删除分组会一并删除成员关联，不删除用户。仅关联该分组的线路会停止展示。

## 智能用户组

新建分组时选择智能类型，然后配置归类规则。

规则由条件和条件组构成。条件组可以设置为 `满足以下全部条件` 或 `满足以下任一条件`，并允许嵌套，用于表达更复杂的组合。

限制如下：

- 单个分组最多 20 个条件
- 条件组最多嵌套 3 层
- 每个条件组至少包含两个条件

### 可用条件

| 条件 | 可选值 |
| --- | --- |
| 会员状态 | 正常、已过期、已禁用、未设置 |
| 会员类型 | 普通会员、永久会员、月付用户 |
| 用户标记 | 全部标记、手动禁用、保号规则禁用、客户端黑名单等 |
| 是否绑定 Telegram | 已绑定、未绑定 |
| 注册时间 | 时间范围 |
| 到期时间 | 时间范围 |
| 有效期剩余天数 | 大于、等于、小于指定天数 |
| 最近播放 | 最近若干天内有播放、若干天未播放、无播放记录 |

在分组列表中选择 `查看规则` 可以查看已配置的规则结构。

## 分组权益

分组可以为成员配置高于系统默认值的权益。

| 权益 | 说明 |
| --- | --- |
| 求片次数 | 该分组成员的求片次数上限，必须大于基础次数 |
| 每日签到奖励 | 该分组成员的签到奖励区间 |

用户同时命中多个分组时：

- 求片次数取各分组中的最高值
- 签到奖励优先取最大奖励更高的区间；最大奖励相同时，再取最小奖励更高的区间

基础求片次数设置为不限时，不能再为分组单独配置求片次数。

## 分组的使用位置

配置好的分组可以在以下位置复用：

- **公告管理**：普通公告和重要公告可指定分组展示，Telegram 私信通知可按分组定向投放
- **线路管理**：线路展示范围可设为指定分组
- **用户管理**：列表支持按分组或未分组筛选，批量修改可将范围限定为某个分组
- **积分与求片**：按分组提供更高的签到奖励和求片次数

## 常见情况

### 智能分组的实际人数和预估不一致

智能分组在任务执行时按当前规则重新匹配。从预估到执行之间用户状态可能发生变化，数量出现差异属于正常现象。批量操作前的预估仅供参考。

### 新建分组时提示权益配置未准备好

分组权益依赖求片和积分配置。等待页面加载完成后再保存；若持续提示，检查求片和积分相关配置是否可正常读取。

### 删除分组后线路不再显示

线路展示范围设为指定分组时，分组被删除会导致该线路失去展示对象。需要重新为线路配置展示范围。
